# 결함

## F-1 (CRITICAL, 게이트 차단) — 해금한 레시피가 재부팅에서 전부 사라진다

`SaveProfile.migrate()` 는 `default_profile()` 을 만들어 놓고 **그 기본 키에
있는 것만** 프로필에서 복사한다. `mod_unlocks` 는 `default_profile()` 에 없고,
`meta_tree` · `unlocks` · `bestiary` 처럼 통째로 옮겨주는 예외 처리도 없다.
저장은 되지만 **로드에서 조용히 버려진다.**

- `scripts/core/smithy.gd:14` — `PROFILE_KEY := "mod_unlocks"`
- `scripts/core/save_profile.gd:100-137` — `migrate()` 의 기본 키 병합
- `scripts/core/save_manager.gd:279` — `_load_from_disk()` 이 `migrate()` 를 탄다
- `grep -rn "mod_unlocks" scripts/` → `smithy.gd` 와 `data/npcs.json` 뿐, `save_profile.gd` 에 없음

측정 (`qa_n11_4.log`, 실제 파일 IO 왕복 포함):

```
before save: ["bongmageom_mod"]
after  load: []
after real file round trip: []
```

**재현 절차 (실기)**

1. 새 프로필로 본거지 → 대장간 진입.
2. 엽전 200 + 촉매 2개를 가진 상태에서 아무 레시피나 `해금 — 200냥`.
3. 카운터가 `1/22`, 카드가 `해금됨` 으로 바뀌는 것을 확인.
4. 게임을 완전히 종료하고 다시 실행 → 대장간 재진입.
5. **카운터가 `0/22` 로 돌아와 있고 엽전 200과 재료 2는 사라진 채다.**

**영향**: 200냥+재료 2를 받아먹고 아무것도 남기지 않는다. 개조 시스템 전체가
한 세션 안에서만 존재한다. 이 상태로 출시하면 순수 자원 손실 버그.

**수정 방향(참고, QA 범위 밖)**: `default_profile()` 에 `Smithy.PROFILE_KEY: []`
를 추가하고 `migrate()` 에서 `unlocks` 와 동일한 문자열 강제 정규화를 태운다.
회귀 테스트는 `tests/unit/test_save_profile.gd` 에 "해금 1건이 왕복에서 살아남는다".

## F-2 (CRITICAL, F-1의 쌍둥이) — 창고 재료(`materials`)도 로드에서 전부 지워진다

같은 `migrate()` 결함의 다른 얼굴이다. `materials` 는 기본 키에 **있지만 값이
빈 딕셔너리** 라, 하위 키 병합이 `{}` 의 키를 순회한다 — 즉 어떤 loot id도 절대
복사되지 않는다. `meta_tree` 는 이 함정 때문에 통째 복사 예외를 받았는데
(`save_profile.gd:131-137` 주석), `materials` 는 받지 못했다.

```
saved  { "whetstone": 9, "ghost_iron": 9, "cinnabar": 7, ... 14종 }
loaded {  }
```

- N11-4 이전(N9-162 창고 도입)부터 있던 결함이지만, **N11-4의 인수 기준을 직접
  깨뜨린다**: 해금 대금이 엽전+재료인데 재료는 부팅마다 0이 된다. 즉 F-1을
  고쳐도 F-2가 남으면 "런 하나 안에서 200냥과 재료 2를 동시에 모아 그 자리에서
  해금" 하지 않는 한 대장간은 영원히 비활성이다.
- 수련(명부수) 트리의 재료 소비 노드도 같은 이유로 부팅마다 리셋된다.

**재현 절차**: 런을 마쳐 재료를 창고에 적립 → 종료 → 재실행 → 대장간/명부수의
재료 표시가 0.
