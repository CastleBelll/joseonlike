## 0. 게이트 전 처리 — 여기서 먼저 문제가 나왔다

지시대로 `git fetch` → `origin/main` 머지 → `git add --renormalize .` → `--import` 을 했고,
그 과정에서 **측정 이전에 고쳐야 할 두 가지**가 드러났다.

### G-1 (BLOCKER, 머지) 머지가 `2c61877`의 가지 굵기 개선을 조용히 되돌렸다

`origin/main` 머지 결과가 `2c61877`보다 **뒤에 있었다**. `_draw_graph` 에서 2c61877이 넣은
QA FAIL-2 수정 — 상태별 가지 굵기(보유 4px / 구매가능 3px / 잠김 2px 파선)와
잠김 가지 색을 `CARD_BORDER_DIM`(대비 1.66:1, 사실상 안 보임)에서
`Color(TEXT_MUTED_ON_DARK, 0.45)`로 올린 것 — 이 **머지에서 사라졌다**.

```
$ git diff origin/main -- scripts/ui/meta_tree_screen.gd
-		if dashed:
-			branch_color = Color(UiPalette.TEXT_MUTED_ON_DARK, 0.45)
-		var branch_width: float = (
-			4.0 if branch_color == UiPalette.GOLD_BORDER else EDGE_WIDTH
-		)
...
-	_canvas.draw_polyline(points, color, width, true)
+	_canvas.draw_polyline(points, color, EDGE_WIDTH, true)
```

브랜치 `CastleBelll/qa-play3`의 `991e82c`(N11-11) 쪽 hunk가 이겼다.
**이 브랜치를 그대로 main에 합치면 2c61877의 대비 수정이 되돌아간다.**
게이트는 `2c61877` 기준이므로 두 파일(`scripts/ui/meta_tree_screen.gd`, `TASKS.md`)을
`origin/main` blob으로 복원한 뒤 측정했다. 코드/데이터 diff는 그 뒤 0이다.

```
$ git diff origin/main --stat -- '*.gd' '*.json' '*.tscn' '*.tres'
(빈 출력 = 코드·데이터가 2c61877과 동일)
```

### G-2 (BLOCKER, 워크트리) CRLF 체크아웃이 테스트 3개를 죽이고 있었다

첫 실행에서 `FAIL 3/600` 이 나왔다 (`test_grades_pacing.gd` 3건).
개별 실행에서도 실패했으나 **커밋된 blob은 전부 LF로 깨끗했다**.

```
$ git cat-file blob origin/main:tests/unit/test_grades_pacing.gd | grep -cU $'\r'
0
$ git ls-files '*.gd' '*.tscn' '*.json' '*.tres' | (CR 포함 파일 세기)
220
```

즉 **워크트리 220개 파일이 CRLF로 체크아웃**되어 있었다. `.gitattributes`가
`*.gd text eol=lf`로 금지하고 있고, 파일 머리에 이 위험을 그대로 적어 두었다:

> "A CRLF working copy turns the newline inside a GDScript multiline string
> literal into \r\n; ... (2026-08-28 landscape QA false-positive — both QA
> worktrees were autocrlf checkouts)."

`test_grades_pacing`의 기대값이 여러 줄 문자열 리터럴이라 `\r`이 끼어 불일치했다.
**지시된 `git add --renormalize .` 은 인덱스만 정규화하고 워킹 트리는 손대지 않는다** —
그래서 이 단계로는 안 고쳐진다. 220개 파일을 각자의 HEAD blob으로 다시 써서 LF로 맞춘 뒤:

```
PASS 600/600 tests
PASS data validation: 19 json files ok
PASS layout_sweep: 12 screens x 11 devices x 2 locales, nothing overflows, clips or scrolls
```

**→ 3건 실패는 제품 회귀가 아니라 워크트리 환경 문제였다. N11 작업과 무관하다.**
후속 조치는 §개선사항 I-2 참조.

### I-1 (BLOCKER) 머지 되돌림을 먼저 해소한다 — G-1
`CastleBelll/qa-play3`를 main에 합치기 전에 `_draw_graph`의 상태별 가지 굵기와
잠김 색 개선을 **2c61877 쪽으로 복원**해야 한다. 이 게이트의 워크트리에는 이미

브랜치를 `origin/main`에 리베이스한다. 지금 상태로 머지하면 대비 수정이 조용히 사라진다.

### I-2 (BLOCKER) QA 워크트리 체크아웃을 LF로 강제한다 — G-2
`.gitattributes`가 이미 규칙을 갖고 있는데 워크트리 220개가 CRLF였다.
`git add --renormalize .` 은 **인덱스만** 고치므로 지시 절차로는 못 잡는다.
QA 세션 프리앰블/`docs/CI.md`의 사전 절차를 다음으로 바꿀 것:
```sh
git config core.autocrlf false
git add --renormalize . && git checkout-index --force -a   # 워킹 트리까지 LF로
git ls-files '*.gd' '*.tscn' '*.json' '*.tres' \
  | xargs grep -lU $'\r' && echo "CRLF LEFT — 게이트 중단"
```
이 검사가 없으면 다음 QA도 똑같이 "3/600 실패"를 제품 회귀로 오인한다
(2026-08-28 landscape QA가 이미 같은 함정에 빠졌다고 `.gitattributes`가 기록하고 있다).

### I-3 (BLOCKER) 방사형 배치를 "면적이 되는가"부터 다시 잡는다 — F-1/F-2
34노드 × 62px 보장은 **508x368 가로 캔버스에서 수학적으로 불가능**하다
(필요 130,700 > 가용 109,300). 완화 sweep을 늘려도 해결되지 않는다. 선택지:
1. **노드 크기를 개수에 맞춰 줄인다** — 캔버스 면적에서 역산한
   `node = clamp(sqrt(area / (n × 1.3)), 40, 56)`. 40px는 터치 최소 44px에 못 미치므로
   가로에서는 2번과 병행해야 한다.
2. **공용 탭을 쪼갠다** — 34노드는 한 화면 방사형에 과하다.
   `refine_*` 계열(정제 계열)을 별도 탭이나 링으로 분리하면 탭당 15~20개가 되어
   현재 알고리즘 그대로 62px가 지켜진다(우치 15노드는 이미 62.0px 정확히 달성).
3. 최소한 **완화 루프를 수렴까지 반복**하고(클램프 후 재검사) 실패 시 노드 크기를
   한 단계 줄여 재시도하는 폴백을 넣는다. 지금은 조용히 겹친 채 끝난다.

권장: **2번(공용 탭 분리) + 3번(수렴 폴백)**. 1번 단독은 가로에서 터치 타깃을 깎는다.

### I-10 (HIGH) FTUE 대화가 출정 바를 막게 한다 — F-17

### I-13 (MEDIUM) 캐릭터 탭의 한쪽 쏠림을 잡는다 — F-4/F-5
10~15노드 구간에서 황금각 나선은 사분면 4/2/2/2까지 치우친다.

분기하는 편이 "사방으로 퍼짐"을 훨씬 잘 만든다. 34노드 나선은 그대로 두어도 된다.
동시에 `mean fill radius`가 0.47~0.62에 머무르므로 **반경 스케일을 0.8 근처까지 밀어**
빈 밴드를 없앤다.

### I-14 (MEDIUM) 본거지 스팟 원판 대비를 올린다 — F-13

### I-15 (MEDIUM) 재료 부족 거부 경로가 검증 불가능하다 — A-4

만들 수 있는 테스트 픽스처를 `tests/unit`에 남겨야 회귀를 잡는다.
