## 2. 작업 방식 (오너 지시, 계속 유지)

- **한 번에 하나씩.** 개발 → 검증 → 커밋/푸시 → 오너 확인 → 다음.
  병렬 워크트리 팬아웃 금지. 예외는 게임 코드를 안 건드리는 에셋 생성뿐.
- main 세션 = 기획·지휘·검수. 코드는 워커가 쓴다.
- 검수는 반드시 직접: `git pull` → `tests/run_tests.gd` → `tools/validate_data.gd`.
- **워커에 지시를 보냈다고 반영된 게 아니다.** 측정 루프 중에는 인박스를
  안 읽는다 — 실제로 반영됐는지 코드·데이터로 확인할 것.
  (실제 사고: 무적 유예 폐기 지시를 두 번 보냈는데 안 읽힌 채 커밋됨 →
  N6-4에서 되돌림.)
- 워커 기동 후 터미널이 실제로 도는지 확인. 프롬프트가 입력창에만
  남아 제출 안 되는 경우가 잦다 → 빈 텍스트 + Enter 전송으로 해결.

## 3. 재부팅 후 복구 절차

Orca 워커·터미널은 재부팅으로 전부 사라진다. 진행 중이던 작업은
**태스크 스펙만 남고 실행은 끊긴다.**

1. `git log --oneline -10` 으로 마지막 커밋 확인
2. `git status` 로 미커밋 잔여물 확인 — 워커가 중간에 죽었으면 워킹트리에
   남아 있을 수 있다. 쓸 만하면 이어서 마무리, 아니면 되돌린다
3. `TASKS.md` 작업 큐에서 다음 항목 선택
4. Orca 재기동 후 새 태스크로 디스패치 (아래 §5 참조)

## 4. 진행 중이었던 것 (재부팅 시점)

**N6-5** — 다음 5건. 완료 여부는 `git log`로 확인할 것:
1. **몬스터 골드 제거** — 골드는 파괴 오브젝트·상자에서만. 경제가 바뀌므로
   메타 트리 비용 재조정 필요(30~50런 목표 유지). 검증기가 `gold_drop`
   잔존을 거부하게
2. **조이스틱 투명도 설정** — 설정 팝업 슬라이더, 프로필 저장
3. **조이스틱 색 중립화** — 주황(나무 버튼과 경쟁) → 채도 낮은 중립 토큰
4. **필드 난잡함 정리** — 솔리드 60 + 데코 110개를 크게 줄이고 군집 배치,
   바닥 타일 변형 밀도·대비도 낮춰서 조용하게
5. **에셋 연결** — 상자(최우선), 픽업 4종, 신장 몸통.
   `new_asset/`의 오너 제공 팩에서 찾아 가공하거나 없으면 등록

미완이면 같은 스펙으로 재디스패치하면 된다.
