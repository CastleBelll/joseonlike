# 연출 / 성능 패스

체감을 다루되 판단은 숫자로 한다. 이 프로젝트에는 이미 `Impact`(히트스톱·화면
흔들림)가 순수 함수로 있고 그 수치는 `data/effects.json`에 있다 — 연출을 눈으로만
고치지 않는 이유가 그것이다.

## 0. 무엇이 거친지 한 문장으로 좁힌다

"매끄럽지 않다"는 대개 셋 중 하나다:

1. **끊김** — 전환이 즉시 컷, 팝업이 팍 튀어나옴, 값이 순간이동
2. **밋밋함** — 사건은 일어나는데 화면이 반응하지 않음(피격·회복·해금)
3. **성능** — 프레임이 떨어져 모든 게 거칠게 느껴짐

셋은 고치는 방법이 완전히 다르다. 먼저 어느 것인지 정한다.

## 1. 픽셀아트 제약 — 어길 수 없는 것

이 게임은 정수 스케일 픽셀아트다. 연출을 넣다가 격자를 깨면 그 연출은 실패다.

- **필터링 금지.** 프로젝트가 `default_texture_filter=0`이다. 스프라이트 임포트에서
  필터를 켜지 않는다.
- **비정수 스케일·회전으로 스프라이트를 늘이지 않는다.** 트윈은 위치·알파·색에
  걸고, 크기를 만질 거면 아주 짧은 구간으로 제한한다.
- 셰이더는 **화면 전체 오버레이**(비네트·암전·색조)로만 쓴다. 스프라이트 단위
  왜곡은 격자를 뭉갠다.
- 페이드는 화면 전체 알파로 충분하고, 이 화풍에는 순서 디더링이 더 어울린다.

## 2. 끊김 — 사이를 채운다

| 증상 | 손볼 곳 |
|---|---|
| 화면 전환이 즉시 컷 | `change_scene_to_file` 호출부. 페이드 아웃 → 전환 → 페이드 인 |
| 팝업이 튀어나옴 | 등장 트윈: 스케일 0.96→1.0 + 알파 0→1, 0.10~0.14초, `EASE_OUT` |
| 값이 순간이동 | 체력바·골드 카운터는 트윈으로 따라가게 |
| 상태 전환이 뚝 | 히트 플래시처럼 **짧고 눈에 걸리는** 신호를 준다 |

시간 상수는 짧게 잡는다. 0.2초를 넘기면 반복 플레이에서 방해가 된다 — 이 게임은
같은 화면을 수십 번 본다.

## 3. 밋밋함 — 반응을 붙인다

새로 만들기 전에 있는 것을 쓴다:

- `Impact.hitstop_sec()` / `shake_add()` — 처치·정예·보스에만. 잦은 사건에 걸면
  슬라이드쇼가 되고 상한 없는 흔들림은 멀미다(그 판단은 코드 주석에 남아 있다).
- `_float_label()` — 무슨 일이 일어났는지 말로 알린다.
- `_play_sfx()` — 소리가 절반이다. 조용한 사건은 안 일어난 것처럼 느껴진다.

**새 수치는 `data/effects.json`에 넣는다.** 연출 상수를 코드에 박으면 다음 사람이
찾지 못한다(ARCHITECTURE.md §6).

## 4. 성능 — MUST / MUST NOT

Godot·GDScript로 옮긴 규칙이다. 프레임이 떨어지면 여기부터 본다.

**MUST**
- 노드 참조는 캐시한다(`@onready`, 멤버 변수). `_process`에서 `get_node`·
  `find_child`를 부르지 않는다.
- 이동·감쇠는 `delta`로 계산한다.
- 자주 생성/파괴되는 것은 `NodePool`을 쓴다. 적·투사체·픽업·구슬·상자·퍼프가 이미
  풀을 탄다.
- 매 프레임 도는 근접 질의는 **공간 색인**을 거친다(`PropGrid`). 월드 크기만큼
  자라는 배열을 매 프레임 훑지 않는다 — 등불과 체가 실제로 그랬다.
- 조건이 넷을 넘어가면 플래그가 아니라 상태다.

**MUST NOT**
- `_process`/`_physics_process`에서 배열·딕셔너리를 새로 만들지 않는다. 매 프레임
  할당은 GC를 부른다.
- 루프 안에서 `instantiate()`/`queue_free()`를 돌리지 않는다.
- 연출 수치를 코드에 하드코딩하지 않는다.
- 타입 없는 배열을 타입 있는 API에 넘기지 않는다. **테스트는 이걸 못 잡는다** —
  `PropGrid.near()`가 Dictionary에서 꺼낸 비유형 배열을 돌려줘 렌더 런에서만 매
  프레임 거부됐고, 552개 테스트는 전부 통과하고 있었다.

## 5. 확인 — 다음으로 넘어가기 전에 잰다

```sh
godot --headless --path . res://tools/playtest.tscn -- --stage=<id> --speed=4 --seed=7 --runs=2
```

`surge fps min/avg`를 읽는다. 서지 구간이 이 게임에서 가장 무거운 순간이라 거기서
버티면 나머지도 버틴다. **연출을 넣기 전과 후를 같은 시드로 비교한다.**

화면을 건드렸으면 `layout_sweep.tscn`, 문구를 넣었으면 `locale_check.tscn`. 렌더
캡처가 필요하면 해상도를 주고 해당 하네스를 돌린다:

```sh
godot --path . --resolution 960x540 res://tools/pause_check.tscn
```

하네스 출력의 `SCRIPT ERROR`를 먼저 본다. 파스 에러가 나면 스크린샷은 옛 파일이
남고, 바뀐 게 없다며 헛돌게 된다.

## 6. 기록

`TASKS.md`에 한 줄 — 무엇이 거칠었는지, 무엇을 넣었는지, fps 전후. 연출은 특히
"왜 이 길이인지"가 사라지기 쉬우니 커밋 메시지에 남긴다.

## 지금 이 프로젝트의 상태 (2026-08-26)

- 셰이더 **0개**. 화면 전체 오버레이가 필요한 연출은 아직 없다.
- `change_scene_to_file` **12곳** — 전부 즉시 컷.
- UI 트윈 27곳. `Impact`의 히트스톱·흔들림은 배선 완료.
- 픽셀 밀도 기준은 대나무숲 괴이(최소 균일 구간 5~10 캔버스 px). 새 연출이 이보다
  고운 디테일을 만들면 축소에서 사라진다.
